This is not real-world data. No people, coaches, studies or external datasets were used. The project has no real labelled outcomes. The dataset exists so the training, evaluation and serving workflow can be built and tested end to end.

## Generation

Every column is drawn independently with NumPy's `default_rng(42)`:

- `Weight`: a uniform integer from 50 to 100 kg.
- `Height`: a uniform integer from 150 to 190 cm.
- `BMI`: Weight / (Height / 100)², rounded to 2 decimals. Training and inference both use `workout_ml.compute_bmi`.
- `Goal`: chosen uniformly from Cut, Bulk and Maintain.
- `Experience`: chosen uniformly from Beginner, Intermediate and Advanced.
- `Plan`: a fixed mapping. Cut → `FatLoss`, Bulk → `MuscleGain`, Maintain → `Maintenance`, followed by `_` and the experience level, for example `FatLoss_Beginner`.

The label is therefore fully determined by `Goal` and `Experience`. `Weight`, `Height` and `BMI` are included so the evaluation can measure whether body measurements add information. By construction they don't, and the evaluation confirms this.

The file is written with `\n` line endings. `.gitattributes` keeps git from converting them, so the checksum is the same on every OS.

## Quality checks

`workout_ml.validate_dataset` runs before training. It rejects:
- missing columns or missing values
- non-numeric measurements
- unknown categories or plans
- weight or height outside the API's accepted range
- BMI values inconsistent with weight and height

`workout_ml.data_quality_summary` reports the following for the current file:

| Check | Result |
|---|---|
| Missing values | 0 |
| Exact duplicate rows | 100 |
| Same inputs with different labels | 0 |
| Largest / smallest class size | 1.30 |

The duplicates come from sampling on a whole-number grid. `load_dataset` drops them before the train/test split, so no identical row can appear in both sets.

## Scope

Weight and height are sampled independently and uniformly, so many combinations are physiologically unlikely, and the data covers a narrower range than the API accepts. The labels encode a design rule, not observed results. Use the dataset to exercise and test the pipeline. It cannot support claims about which plan suits or works for a real person.
